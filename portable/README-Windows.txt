Hex 本地对弈测试 · Windows 10/11 x64 优化 CPU 离线版

开始使用
1. 将整个 ZIP 解压到可写目录，例如 D:\HexLocal。不要直接在压缩包里运行。
2. 双击 START_HEX.bat，首次默认使用第 880 轮模型；之后恢复上次选择。浏览器会自动打开。
3. 保持黑色控制台窗口打开；关闭窗口或按 Ctrl+C 会停止本地服务。
4. 如需使用第 750 轮模型，关闭原窗口后双击 START_750.bat。

本包自带 Python、ONNX Runtime 原生 C++ CPU 推理内核、Numba、MSVC 运行库、750、800、880 三个训练模型和 Azalea 参考模型。
界面由 Python 运行，神经网络由原生 C++ 推理内核计算，搜索热点循环由 Numba/LLVM 编译为本机机器码。
不需要安装 C++ 编译器或 PyTorch。首次启动会编译并缓存搜索内核，后续启动会复用缓存。
运行时不需要联网，不需要安装 Python、CUDA 或独立显卡。
仅支持 64 位 Intel/AMD Windows；不是 Windows ARM 原生版。

更新旧版本
关闭旧窗口，将新包完整解压到新目录，再双击新目录中的 START_HEX.bat。
旧 games 文件夹可复制到新目录保留棋谱。不要自行挑选部分程序文件覆盖。
如果使用专门发布的更新补丁，请关闭旧窗口，将补丁全部内容解压覆盖软件根目录，按补丁说明启动。

添加与切换模型
软件根目录 models 支持复制新增模型，递归扫描子文件夹。每个模型需要 .onnx 与同名 .onnx.json。
网页“你的训练模型”内选择后点击“切换并新开局”；旧局自动保存，选择会记忆。
空闲时每 5 秒自动发现，也可手动刷新。750、800、880 轮均已附带，880 为约 10% 教师数据混合训练模型。
不完整或不兼容的新文件会显示错误原因，不影响其他有效模型。详细说明见 models\README.txt。
START_HEX.bat 恢复上次选择；START_750/800/880.bat 可直接指定轮次。

CPU 线程设置
网页“你的训练模型”卡片下可选择 4～16 个 CPU 推理线程，点击“应用线程设置”立即生效。
对战或分析进行中请先暂停；切换会保留当前棋盘和搜索树。
设置保存到 settings.json，重新启动仍会保留；两个模型共用所选线程配置。
默认最多 4 线程，较少逻辑处理器的电脑初始值会自动减少。
线程数是可参与计算的 CPU 线程数，不是分配固定物理核心；16 线程不保证比 4 线程快。

手动设置开局
先选择己方为人类或 Azalea、己方先后手，再点击“新建手动开局”。
在棋盘上交替放置红棋、蓝棋，手数不限。此时模型不会自动抢走下一步。
点击“完成开局，开始对弈”，模型会从这个局面接着下。
“新开一局”创建普通空棋盘；这两个按钮都会新建一局。

模型分析
选择分析模型，然后点击“分析当前局面”，显示前三个候选、Q 值与后续变化。
自动对战中点击“暂停并分析”，会等待当前一步完成后暂停和分析。
点击候选或后续坐标可预览；预览不改变真实棋盘。
点击“返回实战棋盘”退出预览；“继续对弈”恢复模型落子。
Q 值是当前执棋方视角的估值，不是校准后的获胜概率。

规则与保存
红方先手，连接上下；蓝方后手，连接左右。本软件不使用交换规则。
棋盘左下角为 A1；底边 A～K，左边从下到上 1～11，和比赛棋谱图一致。
对手固定为所选训练模型，己方可选人类或 Azalea。
游戏记录保存在 games 文件夹；也可以在网页中“导出棋谱”。
logs 保存运行日志；cache 仅为首次推理产生的缓存。
默认每步搜索 800 次，保持原有 FP32 精度和搜索规则；没有通过减少搜索次数来加速。
若默认端口 8765 被占用，启动器会选择后面的空闲端口。

比赛棋谱与打谱
“导入 TXT / JSON”可读取 GB2312 比赛 TXT 或本软件 UTF-8 详细 JSON。
TXT 上限 256 KB；详细 JSON 上限 8 MB，可保存整局逐手评语和分析变化。
导入后从空棋盘开始查看；使用首手、前后一步、末手、滑块或点击棋谱中的某一手跳转。
查看时模型不会自动落子，可分析当前局面的前三个候选和后续变化。
“从此局面续弈”会另建棋局，保留当前前缀，原棋谱另存不被改写。
续弈先进入手动开局状态，可继续摆棋或点击“完成开局，开始对弈”。

比赛 TXT 严格使用 {[HEX][先手队 R][后手队 B][结果][时间地点][赛事];R(E,7)MARK[1];B(E,6)...}。
只有 MARK[-2]、MARK[-1]、MARK[0]、MARK[1]、MARK[2] 可作为单手注释。
在“队名、赛果与赛事信息”填写资料后可导出；文件名按 HEX-先手队 R vs 后手队 B-赛果-时间地点-赛事.txt 生成。
Windows 文件名不能含冒号等字符，这些字符会在文件名中换为下划线，文件内容保持原文。
TXT 必须声明先手胜或后手胜。未结束且尚无裁定的棋局，请先保存详细 JSON，不会虚构胜负。
声明胜方但棋盘尚未连通的节选或认输棋谱允许导入，并提示尚不能验证胜负；明确矛盾、重复落子、错误颜色会拒绝。
SAMPLE_HEX.txt 是用户提供格式的示例节选，可直接导入，不能作为已验证的完整获胜棋谱。

逐手评注
选中某手后的局面，可手动填写 MARK 和详细评语，然后保存评注。
也可先“分析当前局面”，再“用当前分析生成”：从上一手落子方视角换算 Q 和 -2～2 分档，
写明评价模型、搜索次数、下一方的三个候选以及已搜索主变化。
默认分档：Q<−0.6 大劣；−0.6≤Q<−0.2 小劣；−0.2≤Q≤0.2 一般；0.2<Q≤0.6 小好；Q>0.6 大好。
这些是局面优劣，不等于此手质量或校准胜率。原 TXT 的 MARK 原样保留，不自动覆盖。
详细文字、Q 和变化图保存在 JSON；比赛 TXT 只写标准整数 MARK，避免破坏比赛格式。
旧版 JSON 按先后手映射为红先蓝后，保留原来的内部棋盘坐标，不改变模型输入和棋局连通关系。

使用提示
首次落子可能需要编译 Numba 内核。
如果浏览器没有自动打开，复制控制台中的 http://127.0.0.1:端口/ 地址。
如果启动失败，请保留 logs 中最新日志。不要只复制一个 BAT 或 Python 文件。
